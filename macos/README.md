# Приложение для macOS

Ловит нажатия **F13..F20** от `keydeck` и выполняет привязанное к кнопке действие.
Работает как агент: живёт в статус-баре (⌨), окна в Dock нет.

## Состояние

Рабочий прототип, проверен на живой плате:

- перехват F13..F20 через `CGEventTap`, нажатие «проглатывается» — клавиша не
  уходит в приложение под курсором;
- действия: `paste`, `type`, `say`, `shell`;
- **окно настроек** (⌨ → «Настройки…»): кнопки нарисованы сеткой 2×4, как на
  корпусе, — выбираешь плитку и правишь действие с текстом, без редактирования JSON;
- **автозапуск при логине** (LaunchAgent);
- статус-бар: состояние разрешения, перезапуск перехвата, открыть конфиг и лог.

Дальше по плану: отдельное действие «отправить команду боту» вместо `shell`.

## Сборка и запуск

Xcode не нужен — достаточно Command Line Tools (`swiftc`).

```sh
./macos/make-signing-cert.sh   # один раз: сертификат для локальной подписи
./macos/build.sh               # собрать macos/build/Keydeck.app
./macos/build.sh --run         # собрать и запустить
./macos/build.sh --clean       # удалить сборку
```

## Автозапуск

```sh
./macos/autostart.sh --install     # включить (нужна собранная .app)
./macos/autostart.sh --status      # что сейчас с агентом и процессом
./macos/autostart.sh --uninstall   # выключить
```

Агент `com.keydeck.agent` в `~/Library/LaunchAgents/` поднимает приложение при
логине. `KeepAlive` выключен намеренно: иначе «Выйти» из меню сразу же
перезапускало бы приложение и выйти было бы невозможно.

Второй экземпляр запуститься не может: при старте приложение проверяет, не
работает ли уже такое же, и выходит. Без этой проверки автозапуск плюс ручной
запуск дали бы два перехватчика на одни клавиши — и двойные срабатывания.

## Подпись и разрешение Accessibility

Без разрешения `CGEvent.tapCreate` возвращает nil, перехват не поднимается — в
логе будет `перехват не запустился: нет разрешения Accessibility`. Выдать:
**Системные настройки → Конфиденциальность и безопасность → Универсальный
доступ**, добавить приложение и включить.

**Сертификат обязателен, а не косметика.** У ad-hoc подписи (`codesign --sign -`)
идентичность привязана к хешу сборки: после **каждой** пересборки macOS считает
приложение новым и требует выдать разрешение заново. `make-signing-cert.sh`
создаёт самоподписанный сертификат `keydeck-dev`, доверяет ему и дальше всё
собирается с ним — разрешение выдаётся один раз и переживает пересборки.
Проверено: пересборка + перезапуск, разрешение остаётся.

Порядок первого запуска, если разрешение не подхватывается:

1. В списке Accessibility убрать **все** старые строки `Keydeck` (кнопка «−») —
   от прежних сборок остаются записи с другой идентичностью, и включается не та.
2. Нажать «+» и выбрать `macos/build/Keydeck.app` (в диалоге путь вставляется
   через **Cmd+Shift+G**).
3. Включить переключатель и перезапустить приложение.

## Привязки

Правятся в окне настроек: кнопки нарисованы сеткой 2×4 в том же порядке, что на
корпусе; щёлкаешь плитку — под сеткой редактируешь её действие и текст/команду.

**Пока окно настроек открыто, приложение ничего не выполняет** — нажатия только
подсвечивают плитку (толстая рамка) и пишутся в лог как `настройки открыты,
действие не выполняю`. Это режим настройки: можно спокойно проверить, какая
кнопка чему соответствует, не запуская деплой и не вставляя текст. Закрыл окно —
действия снова работают.

Файл — `~/Library/Application Support/keydeck/bindings.json`,
создаётся при первом запуске. Индекс в массиве = кнопка: **0 — верхняя левая
(F13)**, 7 — нижняя правая (F20); порядок совпадает с `KEY_PINS` в прошивке.

| `action` | Поля | Что делает |
|---|---|---|
| `paste` | `text` | кладёт текст в буфер обмена, шлёт Cmd+V, возвращает прежнее содержимое |
| `type` | `text` | печатает текст напрямую через `keyboardSetUnicodeString`, буфер не трогает |
| `say` | `text` | произносит текст системным голосом |
| `shell` | `command` | выполняет команду через `/bin/sh -lc` |
| `none` | — | ничего (нажатие проходит дальше) |

**Отдельно у каждой кнопки есть поле `say`** — что произнести после выполнения
действия. Так одна кнопка может и команду выполнить, и озвучить результат:

```json
{ "action": "shell", "command": "~/deploy.sh", "say": "Деплой запущен" }
```

Для `shell` текст произносится **только при успешном завершении** команды: говорить
«деплой прошёл» при упавшей команде было бы враньём. Для остальных действий — сразу.
`say` работает и с `action: "none"` — тогда кнопка просто проговаривает фразу.

**Поле `press`** — какую клавишу нажать после действия. Нужно, когда одного
действия кнопки мало: например, вставить текст и сразу отправить его Enter'ом.

```json
{ "action": "paste", "text": "Готово, проверяй", "press": "return", "delay": 400 }
```

Доступны `return`, `tab`, `escape`, `space`, `down`, `up`. Для `shell` клавиша
нажимается только при успешном завершении команды (как и `say`). Порядок при
срабатывании: действие → пауза → клавиша → озвучка.

**Поле `delay`** — пауза перед клавишей в миллисекундах, по умолчанию **250**.
Пауза обязательна на практике: кнопка нажимается быстрее, чем приложение-получатель
успевает увидеть вставленный текст, и Enter уходит в пустое поле. Именно так ведёт
себя Telegram — со второго нажатия работает, потому что текст уже на месте. Если
приложение медленное или текст печатается посимвольно (`type`), паузу стоит
увеличить до 400–600 мс.

**Буфер обмена.** `paste` кладёт текст в буфер, шлёт Cmd+V и через 0.4 с возвращает
прежнее содержимое. Если не хочется, чтобы буфер участвовал вообще, используйте
`type`: он печатает текст напрямую и буфер не трогает.

**Поле `description`** — короткая подпись на карточке подтверждения. Пишется
крупно. Для `shell` команда остаётся под ней мелким текстом, чтобы сверить,
если надо. Без подписи у команды крупно стоит слово «Команда». У `paste`,
`type` и `say` без подписи крупно выводится сам текст.

**Поле `confirm`** — спрашивать подтверждение перед выполнением. В настройках это
галочка «Спрашивать подтверждение». При нажатии всплывает карточка: крупно —
подпись или текст действия, мелко — команда, значком — клавиша (`⏎`) и голос
(фраза, которую скажет `say`), и дальше:

- **та же кнопка** — выполнить;
- **любая другая кнопка** — отмена (и её собственное действие не выполняется);
- кнопка **«Отмена»** в карточке или **30 секунд** без ответа — тоже отмена.

```json
{ "action": "shell", "command": "say \"Готово\"", "confirm": true }
```

Карточка показывается поверх других окон, **не забирая фокус**: приложение, в
котором ты работаешь, остаётся активным, а подтверждение идёт кнопкой. Подходит
для деплоя и других необратимых действий.

`paste` надёжнее в большинстве приложений; `type` — там, где вставка из буфера
нежелательна. `shell` даёт всё остальное: скрипты, боты, цепочки.

В окне настроек есть кнопка **«Подставить пример»** — она вписывает короткую команду,
чтобы не набирать её вручную.

Внизу окна две кнопки: **«Сохранить и закрыть»** и **«Отмена»** (она же Esc).
Отмена просто закрывает окно — правки не сохраняются. Файл привязок читается
**при каждом открытии окна**, поэтому отдельной кнопки «перечитать» нет.

Открыть настройки можно из меню ⌨ или через ⌘, — сочетание появилось вместе с меню.

В полях работают обычные ⌘C / ⌘V / ⌘X / ⌘A. Ради этого приложению приходится
держать **скрытое главное меню** с разделом «Правка»: в macOS эти сочетания
обрабатываются пунктами меню, а не самими текстовыми полями, а у приложения-агента
меню по умолчанию нет — без него копирование и вставка просто не срабатывают.

Лог: `~/Library/Logs/keydeck.log` — старт, состояние перехвата и каждое нажатие с
выбранным действием, включая текст для озвучки. **Туда же попадает вывод команд**
(строки с пометкой `[вывод]`): без этого он уходил в стандартный вывод приложения,
а у автозапуска это `~/Library/Logs/keydeck.agent.log`, где его никто не видит.
Читается потоком, поэтому длинные скрипты не зависают на заполненном буфере.

## Готовые приёмы

**Проговорить по нажатию** — действие `say`, текст в поле.

**Проговорить по завершении задачи** — любое действие плюс текст в поле
«Произнести после выполнения»; для команды он сработает только при успехе. То же
самое можно сделать и внутри команды, если нужна развилка:

```sh
~/task.sh && say "Готово" || say "Ошибка"
```

## Ключевое архитектурное решение

Как приложение узнаёт о нажатии. Два пути:

| Путь | Плюсы | Минусы |
|---|---|---|
| **F13..F20 + глобальный перехват** (`CGEventTap`) — реализовано | работает уже сейчас, ничего не меняем в прошивке; клавиши свободные, конфликтов нет | нужно разрешение Accessibility; системные шорткаты мака иногда перехватывают раньше |
| **Своя BLE GATT-характеристика** — устройство шлёт «нажата кнопка N» напрямую, без HID | надёжнее, не зависит от раскладки и перехватов | надо писать BLE-центр (`CoreBluetooth`), переделывать прошивку; больше работы |

Начали с первого: он даёт результат сразу и не запирает — прошивка и так
отправляет только код, так что переезд на GATT (или добавление его рядом) не
ломает приложение, меняется один слой транспорта.

## Известные грабли

- **F13..F20 могут быть заняты** системными настройками (Mission Control,
  Spotlight, яркость/звук). Если кнопка не доходит — проверить
  System Settings → Keyboard → Keyboard Shortcuts и освободить клавишу.
- **Accessibility нужен и на перехват, и на синтез событий** (вставка текста,
  Cmd+V) — это одно и то же разрешение.
- **`shell` наследует окружение приложения-агента**, а не терминала. Если
  скрипт лежит не в домашней папке, в команде нужен полный путь или явный `cd`.
- **Раскладка.** BLE-клавиатура эмулирует US-QWERTY; для F-клавиш неважно.
  `type` с не-ASCII текстом зависит от приложения-получателя — если текст не
  появляется, использовать `paste`.
- Подробности про BLE-сторону — в
  [`../docs/ble-hid-macos-gotchas.md`](../docs/ble-hid-macos-gotchas.md).
